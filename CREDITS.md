# Credits: ARC32 (legacy 32-bit ARC, ARCtangent-A4) module

This module is a community SLEIGH module that Ghidra-Rare imported, tested and fixed. The
original processor specification was written by cyrozap as a Ghidra pull request. Ghidra-Rare's
changes are listed below.

## Ghidra-Rare changes

1. **Instruction decoding reworked after differential testing against GNU libopcodes 2.25.1**
   (both byte orders). The ALU, single-operand, branch/jump/loop and load/store constructors are
   now generated by `tools/gen_arc32.py` into `data/languages/ARC32_ops.sinc`, with separate
   constructors for the unconditional and conditional forms, flag-setting and non-flag-setting
   forms, `j`/`j.f` and each access size, so that p-code never branches on a value that is
   constant for the encoding (such branches hid unconditional jumps from analysis and stopped the
   decompiler from recovering switch jump tables). Problems found and fixed:
   - short immediates (`r61`/`r63` indicators) in every operand position, including the
     "op #shimm,#shimm" encodings, the rule that the C field decides the flag-setting behaviour
     when both B and C hold a short immediate, and short immediates being unconditional (the D
     field overlays Q, F and N);
   - the `0` destination (A = 61-63 discards the result);
   - long immediates in all source positions, `j`/`jl` to a long immediate, `st` of an
     immediate to an immediate address;
   - the objdump aliases `mov`, `asl`, `rlc` for `and`, `add`, `adc` with equal source
     registers; condition names (`z`, `nz`, `p`, `n`, `c`, `nc`, `v`, `nv`, ...) and suffix
     order (`.f` before the delay-slot mode); extension condition codes 0x10-0x1f;
   - load/store address modes (`.a` write-back, `.x` sign extension, `.di`), register+register
     and register+offset loads, `lr`/`sr` with register, short- and long-immediate register
     numbers;
   - user extension majors 0x16-0x1d and unused single-operand sub-opcodes decode as
     `ext_instruction` / `extsopNN` (core-specific) instead of being rejected.
2. **Missing instructions added** (the pull request's TODOs): `max`, `min`, `norm`, plus `swap`,
   `mul64`/`mulu64` (32x32 multiplier with `MLO`/`MMID`/`MHI`), `rrc`, `brk`/`sleep`/`swi`.
3. **Semantics** checked in Ghidra's emulator (42 sequences per byte order): flags and carries
   of `add`/`adc`/`sub`/`sbc` (the pull request's flag code was rewritten), logic and shift flags,
   `flag`, conditional execution, loads and stores in every mode, `lr`/`sr`, `bl`/`jl` link value
   (blink holds the STATUS-register format: flags in bits 31-25, PC/4 in bits 23-0),
   `j.f` restoring the flags.
4. **Delay slots** (pull request FIXME): all three modes — ND (no delay slot), D (always
   executed), JD (executed only when the branch is taken; a nullified slot is skipped) — for
   `b`, `bl`, `lp`, `j` and `jl`, with unconditional forms that have no fall-through path.
5. **Zero-overhead loops** (pull request FIXME): `lp` marks the loop end through context
   (`loopEnd`/`loopStart`), and the instruction at the loop end branches back to the loop start
   while `lp_count` is not exhausted, so analysis, the emulator and the decompiler see an
   ordinary loop.
6. **Loops set up with `sr` to `lp_start`/`lp_end`** (how GCC writes single-instruction loops,
   e.g. multi-bit shifts on cores without a barrel shifter): a dedicated `sr ...,[lp_end]`
   constructor and a Java analyzer (`src/main/java/arc32/Arc32LoopAnalyzer.java`, "ARC32 SR
   Zero-Overhead Loops") that finds the loop addresses by constant propagation and sets the same
   loop-end context as `lp`.
7. **Indirect calls written as jumps** (`lr blink,[status]` / `j.d [rN]` / `add blink,blink,2`,
   as GCC writes calls through a register): a Java analyzer
   (`src/main/java/arc32/Arc32IndirectCallAnalyzer.java`, "ARC32 Indirect Calls") marks the jump
   as a call, so the code it returns to is disassembled (in the zlib sample 2.3 KB of code were
   unreachable before) and the decompiler shows a call.
8. **cspec** rewritten from GCC 4.5.4 output: arguments in r0-r7 then on the stack from sp+16;
   r16-r23, fp and sp callee-saved (r24/r25 are not allocated by GCC); 64-bit results in r1:r0;
   `blink` as the return address; 4-byte alignment of 64-bit types; 4-byte `wchar_t`.
9. **pspec**: program counter register (`pc`, needed by the emulator), loop context,
   auxiliary register names (`STATUS`, `SEMAPHORE`, `LP_START`, `LP_END`, `IDENTITY`, `DEBUG`,
   `MULHI`) in a word-addressed `auxregs` space.
10. **DWARF register map** confirmed against GCC 4.5.4 DWARF output (r0-r31 by number, fp = 27,
   sp = 28, lp_count = 60); the pull request's "mappings are guessed" FIXME is resolved.
11. **Stand-alone extension build** (`build.gradle`, `extension.properties`,
    `data/buildLanguage.xml`, `data/sleighArgs.txt`) replacing the in-tree Gradle file.
